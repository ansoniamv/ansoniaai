# Generated pro forma models: Anthropic setup

The deal page's **Generate model** button runs the full-underwrite skill as an Anthropic Managed Agents session.
Anthropic hosts the agent loop and a Linux container for each run. The `generate-model` edge function starts the
session and collects the model when it ends.

This folder holds the Anthropic side, synced to the account with the `ant` CLI:

| Path | What it is |
|---|---|
| `agents/underwriter.md` | The agent: Opus 5.5, the skill, web search and fetch, the `auto` permission policy. |
| `environments/underwriter.yaml` | The container: cloud, unrestricted networking (see the comment in the file). |
| `skills/full-underwrite/SKILL.md` | The platform entry point: inputs, outputs and what changes from the desktop skill. Written by hand. |
| `skills/full-underwrite/UNDERWRITE.md`, `scripts/` | The desktop skill's rules and Python, generated by `scripts/sync-underwrite-skill.ts`. Don't edit them here. |

## One-time setup

1. **Install `ant`** (1.30.0 or later) and sign in: `ant auth login`, or set `ANTHROPIC_API_KEY` to the platform's
   key. Releases: github.com/anthropics/anthropic-cli/releases.

2. **Create the agent, the environment and the skill.** From the repo root, so `claude-lock.json` lands there:

   ```sh
   ant apply --dry-run -v anthropic/agents/underwriter.md anthropic/environments/underwriter.yaml
   ant apply anthropic/agents/underwriter.md anthropic/environments/underwriter.yaml
   ```

   The agent file references the skill folder, so the skill is uploaded in the same run. Check: the plan lists three
   creates (agent, environment, skill), and `claude-lock.json` then holds three ids. Commit `claude-lock.json`.
   *Unverified:* that the skill folder (about 100 KB) uploads in one piece.

3. **Check the container can recalculate.** Recalculation needs LibreOffice. The container's image isn't documented,
   and the desktop run had no LibreOffice either (it drove Excel instead). Run the probe, about $0.50 to $2:

   ```sh
   MODEL_AGENT_ID=agent_... MODEL_ENVIRONMENT_ID=env_... ANTHROPIC_API_KEY=... \
     deno run --allow-net --allow-env --allow-read scripts/model-env-probe.ts "<path to 00. Pro Forma - Template.xlsx>"
   ```

   The last line says `RECALC: works`, `RECALC: no LibreOffice` or `RECALC: fails (...)`. With anything but
   `works`, runs still produce a model, but without saved values: it shows its numbers only once opened in Excel.
   The skill's Setup section covers that fallback. If apt can't install LibreOffice, adding it to the environment's
   `packages` config is the next thing to try. The API reference lists that field but doesn't document its contents.

4. **Apply the migration** `supabase/migrations/20261102120000_deal_models.sql` in the Supabase SQL editor.
   Check: `select count(*) from deal_models;` returns 0, and the `deal-models` bucket exists.

5. **Add the inputs to Brain** (admin): upload `00. Pro Forma - Template.xlsx` with the category "Pro forma template
   (model runs)", and `2026 Affordability Novogradac.xlsx` with "Affordability workbook (model runs)". The newest
   file in each category is the one runs use. Brain also reads each upload with AI, as it does every file.

6. **Set the function secrets** and deploy:

   ```sh
   supabase secrets set MODEL_AGENT_ID=agent_... MODEL_ENVIRONMENT_ID=env_... MODEL_RUN_BUDGET_USD=15
   supabase functions deploy generate-model
   ```

   Deploy only from code that includes `main`: a deploy from a stale branch rolls other fixes back.

7. **Budget.** One run's cost is capped at `MODEL_RUN_BUDGET_USD` ($15 by default) on the session itself. The desktop
   Greyeagle run used about $8 of tokens at list prices. The in-app cap is $90 a month (`AI_MONTHLY_BUDGET_USD`) under
   a $100 Console limit, so a few runs would use most of a month. Raise both before relying on this. A run won't start
   unless its full cap fits in what is left of the month.

## Updating the skill

When the desktop skill changes:

```sh
deno run --allow-read --allow-write scripts/sync-underwrite-skill.ts "<path to the desktop full-underwrite SKILL.md>"
ant apply anthropic/agents/underwriter.md
```

The sync rewrites `UNDERWRITE.md` and `scripts/` only. If the desktop skill gains a new step that needs a platform
rule (a new question for Chase, a new input file), add that rule to `SKILL.md` by hand.

## How a run works

1. `generate-model` `start` picks the newest T12, the rent roll dated closest to it and the newest OM (the user can
   change them), plus the newest template and Novogradac workbook in Brain. It uploads them, with a `run.json` brief,
   through the Files API, and creates the session with a budget and the first message.
2. The agent follows `SKILL.md`. It sends `PROGRESS:` lines, saves the model after each tab and writes `qc.md` and
   `result.json` to `/mnt/session/outputs/`.
3. While a run is open, the deal page calls `check` every 20 seconds. Each check reads the new events, denies any
   tool call the server holds for approval (nobody is watching), and saves the latest progress line. When the
   session stops (`end_turn`, `retries_exhausted` or `budget_reached`), the check copies the newest `.xlsx` and
   `qc.md` into the `deal-models` bucket, logs the session's list cost to `ai_usage_log` and deletes the uploaded
   inputs. The session is kept in the Console as the record of the run.
4. A run nobody is watching is collected the next time someone opens the deal.

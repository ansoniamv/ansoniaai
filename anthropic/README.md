# Generated pro forma models: Anthropic setup

The deal page's **Generate model** button runs the full-underwrite skill as an Anthropic Managed Agents session.
Anthropic hosts the agent loop and a Linux container for each run. The `generate-model` edge function starts the
session and collects the model when it ends.

This folder defines the Anthropic side:

| Path | What it is |
|---|---|
| `agents/underwriter.md` | The agent: Opus 5.5, the skill, web search and fetch, the `auto` permission policy. |
| `environments/underwriter.yaml` | The container: cloud, unrestricted networking (see the comment in the file). |
| `skills/full-underwrite/SKILL.md` | The platform entry point: inputs, outputs and what changes from the desktop skill. Written by hand. |
| `skills/full-underwrite/UNDERWRITE.md`, `scripts/` | The desktop skill's rules and Python, generated by `scripts/sync-underwrite-skill.ts`. Don't edit them here. |

The platform's Anthropic API key is held only in Supabase's function secrets, and the Console account it belongs to
is someone else's. So nothing here is created from a laptop: `scripts/bundle-underwriter.ts` packs this folder into
`supabase/functions/generate-model/underwriterBundle.ts`, and the function's admin **Set up** action creates the
environment, the skill and the agent with the platform's own key. It saves their ids in `model_agent_config`, so the
agent always sits in the same workspace as the key.

## One-time setup

1. **Migrations:** `20261102120000_deal_models.sql` and `20261102130000_model_agent_config.sql`.
2. **Brain:** the newest file in "Pro forma template (model runs)" is the template, and the newest in "Affordability
   workbook (model runs)" is the Novogradac workbook.
3. **Deploy** `generate-model`, only from code that includes `main`.
4. **Set up** (admin): on any deal's Pro forma model card, press **Set up**. The toast lists what was created.
5. **Check container** (admin): starts a short session, capped at $2, that only installs LibreOffice and recalculates
   the template. Its report ends with `RECALC: works`, `RECALC: no LibreOffice` or `RECALC: fails (...)`. With
   anything but `works`, runs still produce a model, but without saved values: the model shows its numbers only once
   opened in Excel. The skill's Setup section covers that fallback. If apt can't install LibreOffice, adding it to the
   environment's `packages` config is the next thing to try. The API reference lists that field but doesn't document
   its contents.
6. **Budget:** one run's cost is capped at `MODEL_RUN_BUDGET_USD` ($15 by default) on the session itself. The desktop
   Greyeagle run used about $8 of tokens at list prices. The in-app cap is $90 a month (`AI_MONTHLY_BUDGET_USD`) under
   a $100 Console limit, so a few runs would use most of a month. Raise both before relying on this. A run won't start
   unless its full cap fits in what is left of the month.

## Updating the skill or the agent

```sh
deno run --allow-read --allow-write --allow-net=jsr.io scripts/sync-underwrite-skill.ts "<path to the desktop full-underwrite SKILL.md>"
supabase functions deploy generate-model --project-ref pyndxntvoixxndbwiawd --use-api
```

The sync rewrites `UNDERWRITE.md` and `scripts/`, and repacks the bundle. If you edit `SKILL.md`, the agent or the
environment by hand, run `scripts/bundle-underwriter.ts` (same flags) yourself. After the deploy, the card shows
"The skill or agent changed since setup" to admins, and **Update** sends only what changed: a new skill version (the
agent uses the latest), a new environment, or a new agent. If the desktop skill gains a step that needs a platform rule
(a new question for Chase, a new input file), add that rule to `SKILL.md` by hand.

## How a run works

1. `generate-model` `start` picks the newest T12, the rent roll dated closest to it and the newest OM (the user can
   change them), plus the template and Novogradac workbook from Brain. It uploads them, with a `run.json` brief,
   through the Files API, and creates the session with a budget and the first message.
2. The agent follows `SKILL.md`. It sends `PROGRESS:` lines, saves the model after each tab and writes `qc.md` and
   `result.json` to `/mnt/session/outputs/`.
3. While a run is open, the deal page calls `check` every 20 seconds. Each check reads the new events, denies any
   tool call the server holds for approval (nobody is watching), and saves the latest progress line. When the
   session stops (`end_turn`, `retries_exhausted` or `budget_reached`), the check copies the newest `.xlsx` and
   `qc.md` into the `deal-models` bucket, logs the session's list cost to `ai_usage_log` and deletes the uploaded
   inputs. The sessions stay on the Anthropic account as the record of each run.
4. A run nobody is watching is collected the next time someone opens the deal.
